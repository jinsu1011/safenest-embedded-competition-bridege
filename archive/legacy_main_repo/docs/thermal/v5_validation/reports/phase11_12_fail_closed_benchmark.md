# Phase 11~12: Fail-Closed 검증 및 성능 벤치마크 보고서

## 1. 개요
* **목적**: 노이즈, 손상된 프레임, 하드웨어 단선 등 다양한 예외 상황에서 V5 시스템이 크래시되지 않고 안전하게 `valid=False` 처리(Fail-Closed)를 수행하는지 검증. 아울러 라즈베리파이 환경에서의 E2E 지연시간 및 처리량을 벤치마크.
* **진행 시간**: 2026-08-11
* **테스트 환경**: 라즈베리파이 5, XIAO-ESP32C6 (UDP 5005)

## 2. Phase 11: Fail-Closed (예외 주입) 검증 결과

| 테스트 항목 | 주입된 예외 상황 | 기대 결과 | 실제 결과 (State) | 판정 |
|------------|----------------|----------|-------------------|------|
| **순서 위반** | `connect()` 호출 전 `read()` 실행 | 에러 및 `valid=False` | `NOT_CONNECTED` | **PASS** |
| **NaN/Inf** | 온도 배열 내 `np.nan` 값 삽입 | 거부 및 `valid=False` | `NAN_OR_INF` | **PASS** |
| **형식 오류** | 프레임 배열 크기 불일치 (10x10) | 거부 및 `valid=False` | `INVALID_FORMAT` | **PASS** |
| **물리적 단선**| 전원/통신선 강제 분리 (타임아웃) | 에러 및 `valid=False` | `NOT_CONNECTED` (Timeout) | **PASS** |
| **복구 성능** | 단선 직후 전원 재연결 | 즉시 정상 복구 | `NOT_HUMAN` (정상 추론 재개) | **PASS** |
| **종료 테스트**| `close()` 호출 후 `read()` 실행 | 에러 및 `valid=False` | `NOT_CONNECTED` | **PASS** |

* **결론**: 어떠한 악의적/물리적 오류 상황에서도 시스템은 죽지 않고 `SensorState`를 올바르게 반환하며 안전하게 방어해 내는 것을 입증함.

## 3. Phase 12: 성능 벤치마크 결과 (30초 연속 구동)

- **테스트 시간**: 30.06 seconds
- **전체 시도 횟수**: 138 Iterations
- **유효 프레임 비율 (신뢰도)**: 135 / 138 (**97.8%**)
- **실측 초당 프레임 수 (FPS)**: **4.6 Hz** 

### ⏱️ 지연시간 통계 (네트워크 수신 + TFLite 추론 포함 End-to-End)
* **Mean (평균)**: 167.92 ms
* **Min (최소)**: 144.43 ms
* **p50 (중앙값)**: 162.70 ms
* **p95 (상위 5%)**: 173.90 ms
* **Max (최대)**: 873.75 ms (초기 통신 스파이크로 추정되나, 시스템에 영향 없음)

* **결론**: 실기기 네트워크 지연과 모델 추론을 합쳐 **p95 기준 173ms**라는 매우 우수하고 안정적인 지연시간을 달성함. 97.8%의 높은 신뢰도를 보여주어 실전 배포에 적합함.
