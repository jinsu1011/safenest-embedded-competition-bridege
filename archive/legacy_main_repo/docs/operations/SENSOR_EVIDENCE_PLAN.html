SCD40(CO2) · HC-SR501 계열(PIR) 실측 증거를 devices/co2/, devices/pir/ 아래에 남기기 위한 작업 절차서

0. 이 문서의 사용 규칙

절대 규칙

  • 측정하지 않은 값은 만들지 않는다. mock_sensor.py 출력, 시뮬레이션 값, 손으로 쓴 숫자는 증거가 아니다.
  • 로그 파일(logs/*.jsonl, *.csv)은 생성 후 사람이 편집하지 않는다. 잘못 찍혔으면 다시 측정한다.
  • 결측을 0으로 바꾸지 않는다. 센서 분리·타임아웃은 null + error_code로 기록하고 SensorState로 표기한다.
  • 한 번에 한 단계만 진행한다. 이전 단계의 통과 기준을 충족하기 전에 다음 단계로 넘어가지 않는다.
  • 배선 변경은 모든 전원(USB-C·외부전원)을 뺀 상태에서만 한다. (docs/operations/HARDWARE_RUNBOOK.md §0)
  • git 커밋·푸시는 승인 후에만. main에 직접 커밋하지 않는다.

1.2 코드 레벨에서 발견한 문제

위치내용영향
devices/co2/src/co2_adapter.py:52-54 read_raw_values()가 (650.0, 45.0, 23.5) 고정값을 반환. 실제 I2C 통신 코드가 한 줄도 없다. 이름은 "Hardware SCD40 I2C Adapter"지만 실체는 상수 스텁. 지금 상태로 돌리면 하드웨어가 없어도 "정상 동작"처럼 보인다.
devices/co2/src/co2_adapter.py:28-38 connect()가 self.connected = True만 하고 무조건 성공을 반환. 센서를 뽑아도 NOT_CONNECTED가 되지 않는다. 결측 시나리오가 현재 코드로는 재현 불가.
devices/pir/src/pir_adapter.py:34-36 read_gpio()가 항상 True 반환. GPIO 접근 코드 없음. 영구 "동작 감지" 상태. 무동작 5분 오검출 0 검증이 구조적으로 불가능.
devices/pir/src/pir_adapter.py:22-32 connect()가 GPIO 설정 없이 무조건 성공. CO2와 동일 문제.
devices/mmwave/firmware/src/main.cpp:528 부팅 이벤트가 "board":"esp-wroom-32"를 보고. 반면 HARDWARE_RUNBOOK.md §3은 XIAO ESP32-C6 핀맵(D4/D5/D0)을 권장. 문서와 펌웨어의 보드가 불일치. 실물 보드를 확인해야 배선표를 쓸 수 있다. → 질문 Q2

작업 트리 상태 devices/mmwave/firmware/capture_serial.py 수정됨(M), monitor_serial.py·logs/live/ 미추적(??). 브랜치를 파기 전에 이 변경을 어떻게 처리할지 결정해야 한다. → 질문 Q11

2. 진행 전 확인이 필요한 사항

아래 답변 전에는 1단계 이후로 진행하지 않는다

핀 번호·포트·보드·전원은 추측하면 하드웨어가 망가진다. 모르는 항목은 "모름"이라고 답하면 확인 절차부터 계획에 넣는다.

번호질문왜 필요한가
Q1SCD40과 PIR을 각각 어느 보드에 붙일 것인가? (ESP32 / 라즈베리파이 5)캡처 경로가 완전히 달라진다. ESP32면 펌웨어 수정 + 시리얼 캡처, Pi면 Python I2C/GPIO 직접 읽기.
Q2실물 ESP32 보드 모델은? (main.cpp는 esp-wroom-32, 런북은 XIAO ESP32-C6)핀 이름(D4/D5/D0 vs GPIO21/22)과 전압 규격이 다르다.
Q3현재 ESP32 펌웨어에 SCD40/PIR 읽기 코드가 이미 있는가? 있다면 어느 파일인가?없으면 펌웨어에 센서 필드를 추가해야 하고, 그러면 재플래싱 절차가 계획에 들어간다.
Q4SCD40 배선 실제 핀: SDA / SCL이 각각 어느 핀에 꽂혀 있는가? (아직 안 꽂았으면 "미배선")WIRING.md의 핵심 내용이며, 이후 명령의 I2C 버스 번호와 직결된다.
Q5SCD40 breakout 제품명과 전원 핀 실크 표기는? (VIN / VDD / 3V3) 레귤레이터·레벨시프터 유무는?5V를 넣으면 안 되는 보드에 5V를 넣으면 센서가 죽는다. 런북 §6-3 필수 확인 항목.
Q6PIR 모듈 정확한 모델명(HC-SR501?)과 OUT 핀 HIGH 전압 실측값은? VCC는 5V인가 3.3V인가?OUT이 3.3V를 넘으면 레벨시프터 없이 MCU에 직결 금지(런북 §7-2).
Q7PIR OUT을 연결할 핀 번호, 그리고 모듈의 홀드타임/감도 볼륨과 재트리거 점퍼(H/L) 현재 설정은?검출 지연·검출률 해석에 반드시 필요하다. 홀드타임이 길면 10회 반복 간격을 그에 맞춰야 한다.
Q8캡처 스크립트를 어디서 실행하는가? (Windows PC에서 USB 시리얼 / 라즈베리파이에서 SSH)PowerShell 명령의 형태가 달라진다. Pi 실행이면 SSH 원격 명령으로 감싼다.
Q9Windows PC에서 ESP32가 잡히는 COM 포트 번호는? (예: COM5)capture_*.py --port 인자. 2단계에서 목록을 뽑는 명령으로 같이 확인할 수 있다.
Q10라즈베리파이 접속 방법: IP 주소, 사용자 계정, SSH 키 사용 여부. (비밀번호는 알려주지 말 것 — 필요 시 본인이 직접 입력)Pi에서 측정하거나 Pi로 파일을 가져올 때 필요.
Q11현재 미커밋 상태인 devices/mmwave/firmware/capture_serial.py(수정), monitor_serial.py·logs/live/(미추적)를 어떻게 할까? (그대로 두기 / 별도 커밋 / stash)브랜치를 파기 전에 정리해야 CO2·PIR 커밋에 섞이지 않는다.
Q12배선 사진 촬영이 가능한가? 촬영본을 어디에 두면 되는가?WIRING.md에 사진이 요구 산출물로 명시되어 있다.

S5. SCD40 원시 판독 경로 확보 CO2
