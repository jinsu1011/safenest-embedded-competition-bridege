오늘 구현한 핵심

현재 범위: 화면에 보이는 CO₂·온도·움직임 수치는 실제 센서에서 수신한 값이 아니라 수동 시연용 예시값입니다. 이번 구현은 화면·원격 상태 전환·긴급 부저 연동까지이며, 센서 실시간 연동 완료를 의미하지 않습니다.

동작 구조

1. 노트북 제어버튼 또는 숫자키 1~6
2. 상태 APIPOST /api/state
3. 저장·출력state.json + LCD 갱신
4. 경보 판단emergency이면 부저 ON

LCD 화면 쪽

static/display.html은 400 ms마다 상태를 조회합니다. 각 상태는 common.css의 색상 변수로 구분되고, 긴급 화면에는 붉은 점멸 효과가 추가됩니다.

상태 revision이 변했을 때만 DOM을 갱신하므로 같은 상태를 반복해서 다시 그리지 않습니다.

노트북 제어 쪽

static/control.html은 버튼과 숫자키 1~6을 지원합니다. 자동 순환은 3초마다 다음 상태로 이동하며 수동 선택 시 즉시 멈춥니다.

공간 이름은 최대 24자로 정리되어 상태 파일에 함께 저장됩니다. 제어 페이지는 1.5초마다 서버 연결 상태를 다시 확인합니다.

피에조 부저 제어 로직

초기화

gpiozero.TonalBuzzer(18)을 만들고 즉시 정지합니다. 기본 주파수는 880 Hz입니다. 초기화 실패 시 오류를 기록하되 화면 서버는 계속 실행됩니다.

상태 연동

상태를 저장한 직후 state == "emergency" 결과를 부저에 전달합니다. 같은 ON/OFF 요청이 반복되면 GPIO 명령을 중복 실행하지 않습니다.

안전 종료

서버 종료 시 stop() 후 close()를 호출합니다. 자동 검증 스크립트도 EXIT·INT·TERM에서 긴급 상태를 해제하도록 방어합니다.

상태 확인

/health에서 활성화 여부, GPIO 사용 가능 여부, BCM 핀, 주파수, 현재 발음 상태, 오류를 확인할 수 있습니다.

재시작 주의: 서버 시작 시 저장된 마지막 상태가 emergency이면 부저가 바로 켜집니다. 실물 부저를 연결하기 전 state.json의 상태를 확인하거나 아래 무음 시험으로 먼저 normal-empty를 저장하세요.

2핀 수동 피에조 부저 배선

Raspberry Pi 전원을 완전히 끈 상태에서 연결합니다. 프로그램은 BCM 번호를 사용하며, BCM GPIO18은 물리 핀 12번입니다.

부저 단자Raspberry Pi물리 핀기준 위치
+ 긴 다리BCM GPIO1812번USB 포트가 아래쪽일 때 위에서 6행, 바깥쪽 열
− 짧은 다리GND14번USB 포트가 아래쪽일 때 위에서 7행, 바깥쪽 열
하드웨어 안전: 전원이 켜진 상태에서 배선을 바꾸지 마세요. 5V 핀에 연결하지 않습니다. 단순 저전류 피에조 소자가 아니라 전류가 큰 부저 모듈·스피커라면 GPIO에 직결하지 말고 트랜지스터 드라이버와 보호 회로를 사용해야 합니다.

팀원용 실행 순서

처음에는 부저를 연결하지 않거나 --disable-buzzer로 무음 시험을 끝낸 뒤 실제 출력을 켭니다.

1

Raspberry Pi 준비 상태 확인

Pi와 노트북을 같은 Wi-Fi에 연결하고 필요한 명령이 설치되어 있는지 확인합니다.

python3 --version
python3 -c 'import gpiozero; print("gpiozero OK")'
command -v chromium || command -v chromium-browser
command -v curl
hostname -I

빠진 항목이 있으면 Raspberry Pi OS에서 다음을 설치합니다.

sudo apt update
sudo apt install -y python3 python3-gpiozero chromium curl
2

프로젝트 가져오기

GitHub 업로드 후에는 clone 방식이 권장됩니다.

git clone https://github.com/<조직또는계정>/<저장소명>.git
cd <저장소명>/safenest_lcd_remote

아직 GitHub에 올리지 않았다면 Windows PowerShell에서 Pi로 복사합니다. 아래 IP는 현재 문서의 예시이므로 실제 Pi IP로 바꿉니다.

scp -r .\safenest_lcd_remote sandi@192.168.1.44:~/
3

실행 권한과 자동 테스트

cd ~/safenest_lcd_remote
chmod +x start_lcd.sh stop_lcd.sh deploy_buzzer.sh
python3 -m unittest -v test_buzzer.py

마지막에 Ran 2 tests와 OK가 표시되어야 합니다. 이 테스트는 실물 GPIO 대신 모의 부저를 사용하므로 소리가 나지 않습니다.

4

부저 없는 무음 서버 시험

부저 출력 없이 API와 웹 화면부터 확인합니다. 이 직접 실행 방식은 Chromium 키오스크를 자동으로 띄우지 않습니다.

python3 server.py --disable-buzzer

노트북에서 http://<라즈베리파이-IP>:8080/control을 열고 1~6 버튼을 눌러 봅니다. Pi 브라우저에서는 http://127.0.0.1:8080/display를 열 수 있습니다.

저장 상태가 긴급이면 제어 페이지에서 1. 정상 · 사람 없음을 선택한 뒤 Ctrl+C로 종료합니다.

5

LCD 키오스크와 실제 부저 실행

전원을 끄고 배선을 마친 뒤 다시 켭니다. 부저가 울려도 안전한 상황인지 주변에 먼저 알립니다.

cd ~/safenest_lcd_remote
bash start_lcd.sh

스크립트가 서버 준비를 확인한 후 Wayland 또는 X11을 자동 선택하고 Chromium을 전체화면으로 엽니다. Raspberry Pi 5의 Chromium GPU 충돌을 피하기 위해 CPU 소프트웨어 렌더링 옵션을 사용합니다.

6

건강 상태 확인

curl -s http://127.0.0.1:8080/health | python3 -m json.tool

실물 부저를 사용할 때는 enabled: true, available: true, pin_bcm: 18, frequency_hz: 880.0, 초기 sounding: false를 확인합니다.

7

노트북에서 제어

start_lcd.sh가 출력한 주소를 노트북 브라우저에서 엽니다. 예: http://192.168.1.44:8080/control.

  • 버튼 또는 숫자키 1~6: 즉시 상태 전환
  • 자동 순환: 3초마다 다음 상태로 이동
  • 수동 선택: 자동 순환 즉시 중지
  • 공간 이름 적용: 최대 24자까지 Pi에 저장
8

실제 경보 2초 자동 시험 — 선택 사항

이 명령은 실제 소리를 냅니다. 현장 인원에게 알리고, 테스트 중지 권한이 있는 사람이 옆에서 실행하세요.
cd ~/safenest_lcd_remote
bash deploy_buzzer.sh

단위 테스트와 GPIO 라이브러리 확인 후 LCD를 재시작하고, 긴급 상태를 약 2초 유지한 다음 자동으로 정상 상태로 되돌립니다. 중단 신호를 받아도 경보 해제를 시도합니다.

9

종료

cd ~/safenest_lcd_remote
bash stop_lcd.sh

Chromium 키오스크와 SafeNest 서버에 종료 신호를 보내고 PID 파일을 정리합니다. 서버 종료 과정에서 부저도 정지·해제됩니다.

문제 해결

제어 페이지는 열리는데 LCD가 안 뜹니다 
cat ~/safenest_lcd_remote/logs/chromium.log
command -v chromium || command -v chromium-browser
echo "$XDG_RUNTIME_DIR"
echo "$WAYLAND_DISPLAY"
echo "$DISPLAY"

Pi의 실제 로그인 화면 세션과 SSH 세션의 Wayland/X11 환경이 다르면 Chromium이 열리지 않을 수 있습니다.

서버 또는 8080 포트가 열리지 않습니다 
cat ~/safenest_lcd_remote/logs/server.log
curl -v http://127.0.0.1:8080/health
ss -ltnp | grep ':8080'
부저가 울리지 않습니다 
python3 -c 'import gpiozero; print(gpiozero.__file__)'
curl -s http://127.0.0.1:8080/health | python3 -m json.tool
tail -n 50 ~/safenest_lcd_remote/logs/server.log

available: false 또는 error가 있으면 GPIO 라이브러리, 핀 점유, 권한, 배선을 먼저 확인합니다. 2핀 수동 피에조인지도 확인하세요.

노트북에서 제어 주소가 열리지 않습니다 
hostname -I
curl -s http://127.0.0.1:8080/health

Pi와 노트북이 같은 네트워크인지, 브라우저 주소에 Pi의 최신 IP와 포트 8080을 사용했는지 확인합니다.
